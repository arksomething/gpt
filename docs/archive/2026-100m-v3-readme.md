# Archived: 100M Llama-Style LM Training From Scratch

> Historical operating notes for the 100M v3 experiment. Paths and defaults in
> this document are preserved for reproduction and are not the current roadmap.
> See [`../../README.md`](../../README.md) and [`../../PLAN.md`](../../PLAN.md).

Train, evaluate, and iterate on a ~100M parameter decoder-only language model
with a full pipeline: tokenizer training, data filtering/tokenization, throughput
benchmarking, training, checkpointing, and evaluation.

The project is model-first and hardware-agnostic. An RTX 4090 is one practical
training target, but the codebase is built around reproducible model experiments
rather than a single GPU SKU.

## What This Repo Contains

- **Model**: Llama-style decoder (`configs/model_100m.yaml`)
  - 12 layers, hidden size 768, SwiGLU (`silu`), RMSNorm, RoPE
  - context length 2048, vocab size 32k
- **Tokenizer**: SentencePiece BPE training + metadata
- **Data pipeline**: C4/Wikipedia/FineWeb streaming, filtering, dedup, memmap export
- **Training loop**: `accelerate`-based training with checkpoint slots and resume flows
- **Evaluation**: validation loss/perplexity + generation sampling
- **Optional remote checkpointing**: upload/download exact-resume checkpoints via Hugging Face

## Where Training Artifacts Are Stored

Use this as the canonical map of generated outputs.

| Path | Artifacts |
|---|---|
| `tokenizer/` | `spm.model`, `spm.vocab`, `tokenizer_meta.json` |
| `data/v3/` | `train.bin`, `val.bin`, `data_meta.json`, `checkpoint.json`, prep logs |
| `runs/throughput.json` | Measured tokens/sec and benchmark metadata |
| `runs/llama-100m-v3/` | Training run outputs (checkpoints, logs, manifests, samples) |
| `runs/llama-100m-v3/step_XXXXXXX/` | Intermediate checkpoints saved during training |
| `runs/llama-100m-v3/final/` | Final checkpoint |
| `runs/llama-100m-v3/train.log` | File logger output |
| `runs/llama-100m-v3/checkpoint_manifest.json` | Slot mappings and checkpoint bookkeeping |
| `runs/llama-100m-v3/artifacts_manifest.json` | Fingerprints and paths for required run artifacts |
| `runs/llama-100m-v3/fixed_prompt_samples.txt` | Periodic qualitative generations |
| `runs/llama-100m-v3/runtime_control.yaml` | Runtime knobs editable during a run |
| `runs/llama-100m-v3/commands.jsonl` | Runtime control command history |

### Remote Artifact Storage (Optional, Recommended)

When `checkpoint_upload.enabled: true` in `configs/train.yaml`, checkpoints and
required run artifacts are uploaded to:

- `checkpoint_upload.repo_id` (currently `ark296/llama-100m-v3-checkpoints`)

Uploaded artifacts include checkpoint folders (`step_*`, `final`) and reproducibility
assets under `artifacts/` (configs, tokenizer files, and `data_meta.json`).

With `local_checkpoint_mode: ephemeral`, local step checkpoints are treated as
temporary and removed after successful upload. If upload fails, the code keeps a
local recovery copy so the run is not lost.

## Setup

1. Create the environment and install project dependencies:

```bash
uv venv
uv sync
```

2. Install a CUDA-enabled PyTorch build that matches your system:

```bash
uv pip install torch --index-url https://download.pytorch.org/whl/cu124
```

3. (Optional) Log in for Hugging Face checkpoint upload/resume:

```bash
huggingface-cli login
```

## Quick Start

All commands below assume `uv run <command>`.

### 1) Train tokenizer (32k SentencePiece BPE)

```bash
uv run train-tokenizer
```

### 2) Prepare tokenized data

```bash
uv run prepare-data
```

### 3) Benchmark throughput (budget guardrail input)

```bash
uv run benchmark
```

### 4) Run a smoke test

```bash
uv run train --smoke
```

### 5) Train

```bash
uv run train
```

Detached session:

```bash
uv run train --launch_screen --screen_name train
```

### 6) Evaluate a checkpoint

```bash
uv run eval --checkpoint runs/llama-100m-v3/final
```

## Data Pipeline Notes

The preprocessing pipeline applies:

- global quality filters (character bounds, alpha ratio, repeated/weird chars, etc.)
- source-specific filters (C4 and Wikipedia heuristics)
- MinHash near-duplicate removal (`dedup_similarity_threshold: 0.85`)

Tune source weights and filter parameters in `configs/train.yaml` under `data_prep`.

## Pre-Tokenized Data

If you want to skip tokenization/prep, download pre-tokenized binaries:

```bash
huggingface-cli download ark296/gpt-training-data --repo-type dataset --local-dir ./data/v3
```

Expected files:

- `train.bin`
- `val.bin`
- `data_meta.json`

## Resume and Checkpoint Workflows

- Resume from local checkpoint:

```bash
uv run train --resume_from runs/llama-100m-v3/step_0005000
```

- Resume from remote checkpoint selector:

```bash
uv run train --resume_from_hf latest
```

Supported selectors: `latest`, `best`, `final`, or `step_XXXXXXX`.

## Hardware Notes

- Single-GPU training is supported out of the box.
- RTX 4090 runs are common in this project, but T4/V100/A100 and other CUDA GPUs work.
- Always run `uv run benchmark` on your target machine and set `budget.hourly_rate`
  in `configs/train.yaml` so cost checks reflect your environment.
